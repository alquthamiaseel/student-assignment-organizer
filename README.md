# Student Assignment Organizer

> Manage your university assignments and exams effortlessly.

A low-fidelity prototype of **Student Assignment Organizer**, generated by an agentic AI project manager from a stakeholder conversation in Slack.

## Screens

- [Home](index.html) — Landing page with links to key features.
- [Course Management](course_management.html) — Allows students to add and manage their courses.
- [Assignment Tracking](assignment_tracking.html) — Enables students to create assignments and track their progress.
- [Calendar View](calendar_view.html) — Displays assignments and exams in a calendar format.
- [Reminders](reminders.html) — Sends notifications for upcoming deadlines.
- [Progress Dashboard](dashboard.html) — Shows an overview of completed and pending tasks.

## What this prototype fakes

- This prototype fakes all functionality; no real data is processed.
- User accounts and reminders are fictitious; actual implementations are not present.

### Student Assignment Organizer – Architecture Diagram

This diagram details the layered architecture of the platform. The client layer is a React SPA interfacing with a REST API (FastAPI). The API delegates business logic by feature modules (user, course, assignment, calendar, reminders, and dashboard). Reminders are handled via background workers using a Redis queue, and outgoing notification flows are shown towards SMTP and push providers. PostgreSQL stores persistent data and a Redis cache supports high-read and job-queuing needs. Cross-cutting concerns, including auth, logging, and monitoring, are highlighted as standalone modules. Major design decisions visible are the separation of background job processing for reminders and the use of an API gateway for secure, validated, and authenticated interactions.

### Student Assignment Organizer – Entity-Relationship Diagram

This ERD models all persistent entities required for functional completeness. The central USER entity relates to COURSE (a student can enroll in many courses), and ASSIGNMENT (each assignment belongs to a course and a user). REMINDER entities are linked to assignments, supporting scheduled and sent notifications. Settings/preferences like REMINDER_PREF are attached to each user. A join table ENROLLMENT supports the many-to-many course-user association. This captures both domain and supporting entities, ensuring both assignments and courses are private per user.

  COURSE {

  ASSIGNMENT {

    uuid course_id FK

### Add Assignment and Schedule Reminder – Sequence Diagram

This diagram illustrates the end-to-end flow for a student adding a new assignment, including authentication, input validation, database insertion, and the background reminder job scheduling and email sending. Alternate flows, like invalid input or unauthorized access, are specified in alt blocks. The reminder scheduling and eventual notification (via a background worker and third-party email service) highlight asynchronous cross-layer interactions crucial for the reminders feature.

```mermaid
sequenceDiagram
  autonumber
  participant ui as UI (React SPA)
  participant api as REST API (FastAPI)
  participant auth as Auth Service
  participant val as Input Validator
  participant svc as Assignment Service
  participant rem as Reminder Service
  participant db as PostgreSQL
  participant queue as Redis (Queue)
  participant worker as Reminder Worker
  participant smtp as Email Provider
  ui->>api: POST /api/assignments { title, desc, course_id, due_date, reminder_settings }
  api->>auth: Validate JWT token
  auth-->>api: 200 OK (user_id) / 401 Unauthorized
  alt Unauthorized
    api-->>ui: 401 Unauthorized
  else Authorized
    api->>val: Validate assignment input
    val-->>api: 200 OK / 422 Unprocessable Entity
    alt Invalid Input
      api-->>ui: 422 Validation error
    else Valid Input
      api->>svc: Create assignment (user_id, course_id, ...)
      svc->>db: INSERT INTO assignments ...
      db-->>svc: Assignment row
      api->>rem: Schedule Reminder (assignment_id, due_date, reminder_settings)
      rem->>db: INSERT INTO reminders ...
      rem->>queue: Enqueue reminder job
      api-->>ui: 201 Created (assignment_id)
    end
  end
  Note over worker: Reminder worker runs asynchronously
  worker->>queue: Dequeue reminder job
  worker->>db: SELECT assignment, user, reminder details
  worker->>smtp: Send reminder email
  smtp-->>worker: 202 Accepted (email sent)
  worker->>db: UPDATE reminders SET sent=true, sent_at=now
  Note over smtp,ui: Reminder is delivered via email before due date
```
